# zig-todo 数据模型设计

| 项 | 内容 |
| --- | --- |
| 存储文件 | `<data-dir>/todos.json` |
| 文档版本 | v0.1 |
| Schema 版本 | `1`（首发） |

---

## 1. 设计原则

1. **人类可读**：便于调试与手工备份
2. **版本化**：根对象带 `version`，不兼容时走迁移
3. **字段显式**：少用隐式默认导致歧义；读取时可填默认，写入写全
4. **稳定排序**：`list` 默认按 `id` 升序；过滤不改变存储顺序

---

## 2. 文件 Schema（version = 1）

### 2.1 根对象

```json
{
  "version": 1,
  "next_id": 4,
  "todos": [ /* Todo 数组 */ ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | number (int) | schema 版本 |
| `next_id` | number (int ≥ 1) | 下一个可用 ID |
| `todos` | array | 任务列表 |

### 2.2 Todo 对象

```json
{
  "id": 3,
  "text": "写架构文档",
  "status": "open",
  "priority": "high",
  "tags": ["docs", "cli"],
  "created_at": 1773120000,
  "updated_at": 1773123600,
  "completed_at": null
}
```

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | u64 | 唯一、正整数 |
| `text` | string | trim 后非空，建议 ≤ 1024 chars |
| `status` | `"open"` \| `"done"` | 枚举 |
| `priority` | `"low"` \| `"medium"` \| `"high"` | 默认 `"medium"` |
| `tags` | string[] | 小写、去重、无空串；可 `[]` |
| `created_at` | i64 | Unix 秒 |
| `updated_at` | i64 | Unix 秒；任意变更时更新 |
| `completed_at` | i64 \| null | `done` 时非 null；`open` 时 null |

### 2.3 完整示例

```json
{
  "version": 1,
  "next_id": 3,
  "todos": [
    {
      "id": 1,
      "text": "初始化仓库",
      "status": "done",
      "priority": "medium",
      "tags": [],
      "created_at": 1773110000,
      "updated_at": 1773115000,
      "completed_at": 1773115000
    },
    {
      "id": 2,
      "text": "写架构文档",
      "status": "open",
      "priority": "high",
      "tags": ["docs"],
      "created_at": 1773120000,
      "updated_at": 1773120000,
      "completed_at": null
    }
  ]
}
```

## 3. 内存模型映射

| JSON | Domain |
| --- | --- |
| `status: "open"` | `Status.open` |
| `status: "done"` | `Status.done` |
| `priority: "low"` | `Priority.low` |
| `tags` | 拥有所有权的切片或 ArrayList |
| 时间戳 | `i64` |

加载失败策略：

- JSON 语法错误 → `CorruptData`，提示备份路径
- 缺字段 → 对可选字段填默认；对 `id`/`text`/`status` 缺失则失败
- `version` 更高 → `UnsupportedVersion`
- `version` 更低 → 走 `migrate.zig`

---

## 4. 迁移策略

```text
load:
  parse JSON
  read version
  while version < CURRENT:
    migrate_to_next(doc)
  validate
  return TodoList
```

规则：

- 每次只迁移 +1 版本，链式升级
- 迁移在内存完成，成功保存后才覆盖主文件
- 迁移前复制 `.bak`

首发仅有 v1，迁移表为空实现，但 **框架先挂上**。

---

## 5. ID 分配

1. 新建任务使用当前 `next_id`
2. `next_id += 1`
3. 删除 **不** 复用 ID（避免脚本/人类混淆）
4. 若检测到 `todos` 中 `id >= next_id`，加载时修正 `next_id = max(id)+1`（自愈）

---

## 6. 过滤与排序（逻辑模型）

过滤谓词（可组合，AND）：

| 条件 | 语义 |
| --- | --- |
| `status` | 精确匹配；默认 list 仅 `open` |
| `priority` | 精确匹配 |
| `tag` | 任务 tags **包含** 该 tag |

排序：

- 默认：`id` 升序
- 可选（Backlog）：priority 权重、`updated_at` 降序

---

## 7. 机器可读输出（`--json`）

列表输出建议为数组（便于 `jq`）：

```json
[
  {
    "id": 2,
    "text": "写架构文档",
    "status": "open",
    "priority": "high",
    "tags": ["docs"],
    "created_at": 1773120000,
    "updated_at": 1773120000,
    "completed_at": null
  }
]
```

单条命令（`show` / `add`）输出单个对象。  
**不必** 输出根上的 `version`/`next_id`（那是存储细节）。
