| 项 | 内容 |
| --- | --- |
| 产品名称 | zig-todo |

| 目标平台 | macOS / Linux（Windows 作为后续增强） |

---

## 1. 产品定位

**一句话**：用 Zig 实现的轻量、快速、可脚本化的本地 Todo CLI。

面向开发者与终端用户，强调：

- **本地优先**：数据落在本机，无需账号与网络
- **键盘优先**：命令清晰、可组合、适合管道与脚本
- **可预期**：行为稳定、错误信息明确、退出码可脚本判断
- **可扩展**：先做核心 CRUD，再分层扩展优先级、标签、项目等

非目标（v1 不做）：

- 云同步 / 多端协作
- GUI / TUI 完整交互界面（可作为远期选项）
- 团队权限、通知推送、日历集成

## 2. 目标用户与场景

### 2.1 用户画像

| 画像 | 诉求 |
| --- | --- |
| 终端开发者 | 快速记录任务、与 shell 工作流结合 |
| 个人效能用户 | 轻量清单，不想打开重型 App |
| Zig 学习者 | 用真实项目练习模块化、文件 IO、测试 |

### 2.2 核心场景

1. 快速记下「马上要做」的事
2. 查看今天/未完成列表
3. 完成或删除任务
4. 按状态、优先级、标签筛选
5. 在脚本中批量查询或统计（非交互）

---

## 3. 产品原则

1. **默认简单**：`zig-todo add "买牛奶"` 即可工作
2. **显式胜过隐式**：危险操作（如清空）需确认或 `--force`
3. **稳定契约**：子命令、退出码、存储格式有版本与迁移策略
4. **可读输出**：人类可读为默认；机器可读用 `--json`
5. **失败可诊断**：错误说明「发生了什么 + 怎么修」

## 5. 命令体验设计

### 5.1 命令风格

采用「动词 + 参数」子命令风格（类似 `git` / `gh`）：

```text
zig-todo <command> [flags] [args]
```

### 5.2 命令一览（产品层）

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `add` | 新增 | `zig-todo add "写架构文档" -p high -t docs` |
| `list` / `ls` | 列表 | `zig-todo list --status open` |
| `done` | 标记完成 | `zig-todo done 3` |
| `undone` | 取消完成 | `zig-todo undone 3` |
| `edit` | 编辑 | `zig-todo edit 3 -d "更新后的描述"` |
| `rm` / `delete` | 删除 | `zig-todo rm 3` |
| `show` | 详情 | `zig-todo show 3` |
| `clear` | 清理已完成 | `zig-todo clear --done` |
| `version` | 版本 | `zig-todo version` |

短别名：`ls` → `list`，`rm` → `delete`。

### 5.3 全局 Flag

| Flag | 说明 |
| --- | --- |
| `--help` / `-h` | 帮助 |
| `--json` | JSON 输出 |
| `--data-dir <path>` | 覆盖默认数据目录 |
| `--quiet` / `-q` | 减少人类可读输出（适合脚本） |

### 5.4 退出码约定

| 码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 一般业务错误（未找到、校验失败） |
| `2` | 用法错误（参数非法） |
| `>2` | 系统/IO 等内部错误 |

## 6. 信息架构与输出

### 6.1 列表默认列

```text
ID  PRI   STATUS  TAGS        TEXT
3   high  open    docs,arch   写架构文档
1   med   done    -           初始化仓库
```

### 6.2 详情

展示完整字段：id、status、priority、tags、created_at、updated_at、completed_at、text。

### 6.3 空状态文案

- 无任务：`No todos. Add one with: zig-todo add "..."`
- 过滤无结果：`No todos matched.`

---

## 7. 数据与隐私

- 默认数据目录：`$XDG_DATA_HOME/zig-todo/`（macOS 可回退 `~/Library/Application Support/zig-todo/` 或 `$HOME/.local/share/zig-todo/`）
- 单文件存储（见技术架构），不上传、不埋点
- 不存储敏感凭证；用户自行负责数据文件权限

---

## 8. 成功指标（产品）

| 指标 | 目标 |
| --- | --- |
| 核心路径时延 | 添加/列表冷启动 < 50ms（本机 SSD，千条内） |
| 学习成本 | 新用户 5 分钟内完成 add → list → done |
| 可靠性 | 异常退出不损坏数据（原子写） |
| 可维护性 | 模块边界清晰，单测覆盖核心领域逻辑 |

## 9. 开放问题

1. ID 用递增整数还是短 UUID？→ **建议 MVP 用递增 u64，展示友好**
2. 是否支持多仓库/多清单文件？→ **v1 单清单，后续用 `--file` 扩展**
3. 是否内置中文界面？→ **MVP 英文 CLI 文案；文档中文；后续 i18n**
